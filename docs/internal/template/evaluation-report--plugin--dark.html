02Executive summary

acme-content-skills is a healthy, genuinely cross-agent library that has cleared the multi-agent bar and now sits one well-scoped push away from the self-proving Gold tier.

This report grades a whole skill library, not a single skill. acme-content-skills ships 15 components in total: 12 content-marketing skills, 2 Claude-only subagents that act as review delegates, and 1 slash command. It was evaluated against all 30 deterministic checks of Standard v0.10, plus an advisory behavioral pass (each skill run against its triggering eval set) and an advisory qualitative review of scoping, descriptions, and chain design. Only the deterministic layer decides the tier; the gate returned exit code 0.

The verdict is Silver (Convergent). Every Bronze (Universal) and Silver (Convergent) check passes: the components are portable and self-describing, carry a consistent acme- prefix, declare both claude and codex as agent targets, and emit clean per-agent native manifests that agree with the canonical library.json. Two Bronze findings are advisory warnings rather than failures: one skill description scores below the clarity bar (U5, acme-content-calendar at 0.62) and one skill body runs over the instruction budget (U7, acme-write-blog-post at roughly 240 instructions). Neither gates the build, but both are worth closing because they erode trigger accuracy and risk dropped steps at run time.

Gold is blocked by exactly three checks, and all three are structural rather than behavioral. There is no self-hosting CI workflow that runs the gate (G2), two of the three declared chains have no regression eval (G3), and there is no curated RELEASE-NOTES.md distinct from the changelog (G5). Importantly, none of these touch how a single skill behaves; they are about the library proving and releasing itself. Each is closeable in well under an hour. The recommended next move is to run the three Gold-blocker prompts in section 07 in order (CI, then chain evals, then release notes), close the two warnings opportunistically, and re-run the gate. That promotes acme-content-skills to a self-proving Gold library without altering a single skill's behavior.

How to read this report

Section 05 is the source of truth: every one of the 30 checks gets its own row with the exact check id, the gate module that produced it, the Standard clause it enforces, and the evidence found. Anything labeled warn or n/a does not block the declared tier. A check is fail only when it blocks a higher tier the library is reaching for - here, Gold.

Want to reproduce the verdict yourself? Clone the library and run node scripts/check.mjs .. The exit code and the per-check lines are the same ones quoted in the gate banner above.

04Methodology & scope

The evaluation runs in three layers, kept strictly separate so the verdict stays honest. Only the first layer decides the tier.

Layer 1 - Deterministic conformance (decides the tier)

The portable Node gate (scripts/check.mjs) runs all 30 checks with real exit codes and no model in the loop. It is the only layer that can move a tier from pass to fail. The same command and the same output run locally and in CI; the gate banner at the top of this report is its verbatim summary. Re-running the gate reproduces the verdict exactly.

Layer 2 - Behavioral (advisory)

Each skill is run against its triggering eval set so that real behavior is observed, not just declared. These results are surfaced as evidence beside the conformance findings. They never decide a pass or fail; a skill that behaves well but fails a deterministic check still fails that check, and vice versa.

Layer 3 - Review (advisory)

A qualitative pass over scoping, descriptions, and chain design adds judgment the gate cannot encode - whether a skill is well-named, whether a chain is sensibly shaped, whether a description will actually trigger. It informs the Insights section and never gates a result.

Confidence & limitations

Conformance findings are exact and reproducible: re-run the gate and you get the same exit code and the same per-check lines. Behavioral and review findings reflect judgment over sampled cases, so treat them as directional evidence rather than proof.

Three checks pass vacuously because the library has nothing for them to inspect: U11 (no MCP servers), G1 (no hooks), and G6 (no deprecations). A vacuous pass is honest - it means the check did not find a problem because there was no surface to find one on - so it is rendered as n/a rather than a green pass.

What each tier guarantees

Bronze / Universal

Portable and self-describing on any agentskills.io agent: valid anatomy, parseable frontmatter, clear names and descriptions, links that resolve, no manifest drift.

Silver / Convergent

Converges cleanly across every declared agent: a consistent prefix, an honest components index, valid chain and command contracts, and complete per-target manifests.

Gold / Advanced

Self-proving: the library builds, checks, documents, and releases itself - CI runs the gate, chains carry regression evals, docs follow the taxonomy, and releases are curated.

08Insights

Qualitative observations from the review layer, beyond pass and fail. These shape the recommendation but do not move the tier.

01

The gap to Gold is plumbing, not craft

All three blockers (CI, evals, release notes) are about how the library proves and ships itself, not about how any skill behaves. That is the best kind of gap to have at Silver: the content is sound, and the climb is mechanical. A maintainer can close it in an afternoon without risking a behavior regression.

02

The chain design is sensible but under-tested

Routing the writing skills through a single acme-style-critic delegate is a clean fan-in: one place owns voice and clarity. The risk is exactly what G3 flags - that shared delegate is a single point of failure for two callers, and right now neither edge is pinned by an eval. Covering both is high leverage because one delegate change could break two skills at once.

03

Cross-agent intent is honest, with a Claude-only tail

The 12 skills genuinely target both Claude and Codex, and the manifests back that up (S1, S6 pass). The 2 subagents and the command are Claude-only by nature, which is fine - subagents and slash commands are Claude surfaces. Worth a one-line note in the docs so a Codex user is not surprised that the writing skills work but the delegate review is Claude-side.

04

The two warnings share a root cause: scope creep in one skill

Both U5 and U7 point at description and budget hygiene. acme-write-blog-post is doing draft plus SEO in one body (U7), and acme-content-calendar is described too generically to trigger well (U5). Tightening scope - SEO into a reference, the calendar description into a sharp action plus trigger - fixes both and tends to improve behavioral scores as a side effect.

05

Documentation is already at Gold strength

G7 through G10 all pass: frontmatter taxonomy, folder READMEs, source docblocks, and the full Diataxis tree are in place. Documentation is often where libraries stall on the way to Gold, so this one is ahead of the curve - the remaining work is in CI and release discipline, not in writing docs.
