### Sensor readings 26-29

- **Reading 26 - the auto-scorer was measuring conformance to the key's granularity, not correctness.** Opus scored 0.42 precision under key 1.0.0 and 1.00 under 1.1.0, on an unchanged advisory. Every one of its "false positives" was either a real unplanted defect or legitimately out of scope; it had none. The mechanism is that a single rich finding which engages two planted entries is classed `review-required` and credited to neither, so the more granular a review, the worse it scores. Seven of Opus's twenty-three findings are still uncredited for exactly this reason, which means its true recall is materially above the 0.62 published here. **Disposition: harness defect, confirmed. Publishing the 1.0.0 numbers would have produced a "Sonnet beats Opus" conclusion that is false.** Needs a scoring rule for multi-entry engagement before any cell can be published as final.
- **Reading 27 - the harness cannot consume an adjudication.** `scoreAdvisory(advisory, key, opts)` accepts only `model`, `effort` and `runId`. It emits a worklist and refuses to finalize, but there is no path to feed resolutions back, so a published pair is hand-computed with nothing checking it. Promoting the four verified defects into the key was the workaround: it converts hand-adjudication into machine scoring for those items. **Disposition: confirmed gap, verified against source. File as a backlog item.**
- **Reading 28 - zero confabulations at every tier, including Haiku at high effort.** Three planted bait entries were available and the cheap tier bit exactly one (`NB-04`, the version spread, which is correct behaviour misread as drift). This does not overturn readings 16 and 17, which recorded a Haiku-tier statute confabulation: it is one fixture and one run, and the fixture's legal content is deliberately wrong in ways a model may simply not reach. **Disposition: recorded as a measured counter-instance, not a calibration. The parity caveat in METHODOLOGY stands.**
- **Reading 29 - only the frontier tier produced findings about the CHECKER, and both verify.** Run 14 reported that `U6` (`reference-links`) iterates `ctx.skills` only, so link rot in a command or subagent body is invisible; and that nothing resolves `.claude-plugin/plugin.json` component-path arrays, so a manifest naming a file that is not on disk passes clean. ### Sensor readings 18-25

18. **U5 (description-score) cannot be passed in any language but English; its ceiling for a non-English description is 0.65 against a 0.7 threshold.** `khalilbenaz` is 349 French skills; 346 parse, and **all 346 score below threshold** in a strictly bimodal distribution (277 at 0.30, 69 at 0.65). Nothing else is dragging them down: zero ANTI hits, zero PLACEHOLDER hits, zero first-person hits across the corpus. The whole deficit is the two English-lexicon gates. The `WHEN` trigger regex fired on **0 of 346** French descriptions while **341 of 346 carry an explicit French trigger clause** (`Se déclenche avec "..."`, `À utiliser quand l'utilisateur ...`). The same-batch English controls: `WHEN` fires on 705 of 1016 (69.4 percent) in `terminalskills` and 134 of 136 (98.5 percent) in `nimadorostkar`. Because `WHEN` is worth 0.35 of the score, a description that cannot match it caps at 0.35 + 0.2 + 0.1 = **0.65, hard below the 0.7 bar** - so the check is unpassable in French by construction, not by degree. Verified by hand on 12 descriptions read in full: they state a concrete capability and enumerate explicit trigger keywords, and the clearest case is `writing-proofreader-fr`, which scores 0.30 while containing "À utiliser quand l'utilisateur veut relire, corriger ou améliorer un texte français" - a word-for-word French rendering of exactly the "use when the user wants..." construction the regex is built to reward. **This is a checker language assumption, not a target defect; the descriptions are good and U5 cannot see them.** It is the same failure shape as reading 10 (the lenny template stem), which ADR 0033 accepted as a scorer defect, so the precedent is settled. Two second-order notes: the 69 that reach 0.65 do so on incidental English loanwords ("audit", "planning", "code review"), which is luck rather than signal; and under `plain-plugin` U5 is off (house provenance, ADR 0029), so **outward grading of a non-English library reports nothing about this at all** - the reading is only visible on the control axis. **REPRODUCED AND DECIDED 2026-08-15 (ADR 0049, v1.14.0).** Re-measured against the live scorer at the same pinned shas during the v1.14.0 ADR pass: French `WHEN` **0 of 346**, `TerminalSkills` **69.4 percent**, `nimadorostkar` **98.5 percent** - all three of this reading's numbers reproduce to the decimal. Two of the options this reading proposed were then measured and **rejected**: the language-independent structural signal fires on **99.9 percent** of 2068 descriptions across all seven corpora (including 94.4 percent of Anthropic's own) and so cannot discriminate at all, and a hand-written pluggable French lexicon reached only **33.2 percent**. What shipped is an ABSTENTION: English function-word density below 0.10 means NOT SCORED, chosen from a sensitivity sweep (median density 0.000 on the French corpus, 0.233 on the largest English one; 343 of 346 French findings withdrawn for a cost of 3 in 1376 English). The evidence for a REJECTED option is worth more than the rejection, which is why the numbers are here rather than only in the ADR. 

**Disposition: ADR + TDD candidate for a later release (per release risk R2-5, NOT calibrated in this branch). The corpus evidence is ready: 346 recorded French strings, a mechanically reproducible distribution, and an explicit failing-ceiling argument. Design question the ADR must answer, since it is not obviously "add French patterns": whether U5 should gain a language-detection escape hatch (score only what it can read, and say so), a pluggable trigger lexicon, or a structural trigger signal that is language-independent - adding French regexes alone would leave the same cliff one language over.**

- **Cross-model unions beat any single run:** the verified-finding union of R9+R10 is larger than either alone (R9 uniquely framed the marketplace "42 chained workflows" overclaim; R10 uniquely found the XYZ+S split, scope creep, and overclaims). For decision-critical reviews, two frontier models on the same target is a measurably better harness than one - this is the panel pattern METHODOLOGY's rigor item 3 anticipated.
- **Single-target caveat:** one plugin, one domain (PM utilities with legal/grammar content). The Opus-vs-Sonnet parity claim needs replication on a structurally-defective target (where R7-style triage depth matters) before it becomes guidance.

8. **THE BATCH'S HEADLINE META-READING: advisory findings must be ground-truth-verified before they become calibration input.** R7 (Sonnet, HIGH effort) confidently triaged all 11 deanpeters U6 errors as "checker false positives" because the linked files exist relative to the REPO ROOT, and recommended weakening U6 to resolve against the repo tree. 9. **S7 (command-contract) assumes one-to-one `maps-to`; real plugins ship one-to-many orchestrator commands.** deanpeters' 6 commands each declare a `uses:` list of multiple skills by design (R7), and phuryn's commands map by naming convention (R8). 10. **U5 (description scorer) cross-corpus evidence is now systematic.** lenny: 50 of 86 descriptions at exactly 0.65, traced to the uniform CONTRIBUTING-template stem "Help users [verb]..." on descriptions whose trigger clauses are actually strong and disjoint (R6 read a dozen). deanpeters: 12 borderline warnings penalizing deliberate brevity (their 200-char web-upload constraint). phuryn: 0.55-0.65 across skills.
