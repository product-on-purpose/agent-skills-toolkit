# The roadmap file

`plan` mode writes this file into the ADOPTER's own repository (never into this toolkit's repository)
at `.askit/onboarding-roadmap.md`, and only after the adopter confirms the roadmap shown to them.
`next` mode reads it back on a later visit. It is plain Markdown, chosen for readability and so the
adopter can hand-edit it, rather than JSON or YAML.

## Shape

```markdown
# Onboarding roadmap

Generated by askit-onboard, plan mode, <date>. Goal: <one line from the interview>.

## Steps

1. [ ] <short step name> - <route: skill or docs page> - done when: <mechanical or self-reported condition>
2. [ ] <short step name> - <route: skill or docs page> - done when: <condition>
...

## Notes
<anything the interview surfaced worth remembering across sessions - current tier, which component
types exist, constraints the adopter named (time budget, which agent targets matter to them).>
```

## Rules `next` mode follows when reading it

- A step is "done" when its checkbox is `[x]`. `next` mode may flip a checkbox itself only when the
  step's own "done when" condition is mechanically checkable (for example "a `library.json` now
  exists" or "`askit-evaluate` now reports Silver") and it has actually re-checked it; otherwise it
  asks the adopter to confirm before marking anything done.
- `next` mode reports exactly the first unchecked step, not the whole list - the roadmap is for the
  adopter to re-read in full if they want to; `next` mode's job is to save them from re-reading it.
- If every step is checked, say so plainly and ask whether the adopter wants a new roadmap (back to
  `plan` mode) rather than silently appending more steps to a finished one.
- If the file does not parse as this shape (hand-edited into something `next` mode cannot read),
  report that plainly and offer to regenerate it with `plan` mode rather than guessing at its content.
