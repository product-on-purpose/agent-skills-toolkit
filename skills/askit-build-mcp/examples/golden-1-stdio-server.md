# Golden example: a bundled stdio MCP server

**Demonstrates:** wiring a server whose code ships inside the plugin, launched over stdio with `${CLAUDE_PLUGIN_ROOT}` so it resolves on a machine the author has never seen.
**Provenance:** authored by `askit-build-mcp` create mode on 2026-07-26 during the SP2b metered authoring pass; raw run artifact under the gitignored `_local/audit/eval-runs/2026-07-26/`.

## Input

> "Our plugin needs a word-count tool. I have the code, it is one Node file, no dependencies. Add it as an MCP server called text-stats."

The create-mode interview (step 1):

| Question | Answer |
|---|---|
| Server name (kebab-case) | `text-stats` |
| Transport | `stdio` - the code is bundled in the plugin |
| Command | `node` |
| Args | `${CLAUDE_PLUGIN_ROOT}/mcp/text-stats-server.mjs` |
| Secrets (env-var NAMES only) | none; one non-secret knob, `TEXT_STATS_LOCALE` |
| Declared targets | `claude`, `codex` |


### `library.json` (the `components.mcpServers` declaration, S3)

```json

  "mcpServers": [
    { "name": "text-stats", "version": "0.1.0", "tier": "universal", "status": "active" }
  ]
}
```

### `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json` (generated, the S6 pointer)

Both native manifests gain the same literal pointer. Never hand-edit them; regenerate with
`node scripts/generators/gen-manifest.mjs . --write --target=all`.

```json
"mcpServers": "./.mcp.json"
```

### The server itself

The runnable sibling of this file is `golden-1-stdio-server.mjs`. In the demo plugin it is installed at
the path the config launches, `mcp/text-stats-server.mjs`; the verification below shows the copy, so the
bytes launched are the bytes shipped here. It is dependency-free: newline-delimited JSON-RPC 2.0 on
stdin and stdout, `protocolVersion` `"2025-06-18"`, answering `initialize`, `tools/list` and
`tools/call` for one tool.

## Why this is golden

- **The launch path uses `${CLAUDE_PLUGIN_ROOT}`, not a bare relative path.** A bundled server is
  started by the agent from the user's project directory, so `./mcp/...` resolves somewhere else
  entirely. This is the defect class recorded in [../references/authoring-mcp.md](../references/authoring-mcp.md)
  and preserved as [anti-nonexistent-server-file.md](anti-nonexistent-server-file.md).
- **The target exists and was launched.** Standard sec 3.9 says a referenced `command` SHOULD be
  resolvable, and no check implements it (`U11` in [../../../scripts/checks/mcp-valid.mjs](../../../scripts/checks/mcp-valid.mjs)
  only requires a non-empty `command` string). The craft doc's rule is that the author carries that
  obligation by running the thing; the transcript below is that proof.
- **All three manifest obligations are satisfied, not just one.** `U11` (well-formed), `S3` (declared in
  `library.json` `components.mcpServers`), `S6` (the literal `"mcpServers": "./.mcp.json"` pointer in
  every declared target's native manifest). `U8` stays green because the manifests are generated from
  `library.json`, so `name` and `version` cannot drift.
- **The env entry is a variable NAME with an empty value** (sec 9). `TEXT_STATS_LOCALE` is not even a
  secret, and it still follows the rule, because the rule is about where values come from at runtime.
- **No `tools` array in the `.mcp.json` entry.** The tool list is advertised by the server at the
  handshake, as the `tools/list` response below shows. Golden example 3 makes that point explicit.
